# Интерактивный прототип Unity — E05 / A13

**Статус: E05 проверен в Unity Editor и Windows Player.** После обновления лицензии Unity `6000.6.0f1` импортировал полный экспорт, прошёл проверки EditMode и собрал Windows x64. Настоящий Player прошёл проверки управления и PhysX-прогулки; получены четыре изображения камеры 1280×720. Проверка выполнялась через Direct3D 11 WARP — программный рендер Microsoft, без конкуренции с Cycles за видеокарту. Это проверка работоспособности, а не измерение производительности GPU. Машиночитаемый результат и хеши артефактов: `Unity/verification-status.json`.

Финальный исходник `.blend`, экспорт проекта и экспорт внутри приложения согласованы по SHA-256: `12620344f8363ba948cff7e8130e722bc7c47d9c77e1c36cf64852a109d5c0ba`.

## Что передано

- `Unity/` — отдельный проект Built-in Render Pipeline без Asset Store, FBX SDK и загружаемых пакетов. В `Packages/manifest.json` перечислены только встроенные модули редактора.
- `Unity/Assets/Scenes/TowerBridge.unity` — начальная сцена. Откройте её и нажмите Play после обновления лицензии в Unity Hub.
- `Unity/Assets/StreamingAssets/scene.bin` — полная оцениваемая геометрия исходной сцены; статические объекты объединены по материалам. Створки, транспорт, колёса, двери автобуса и суда имеют отдельные группы.
- `Unity/Assets/StreamingAssets/scene.json` — цвета материалов, метры, схема осей, исходный SHA-256, описания частей и трансформации каждого кадра. Экспорт содержит **107 групп и 152 640 трансформаций**.
- `tools/export_unity.py` — воспроизводимый экспорт из Blender, не изменяющий `.blend`.
- `Unity/compile_sources.py` — независимая компиляция C# против библиотек установленного Unity; не заменяет запуск редактора.
- `Unity/build_windows.ps1` — воспроизводимая пакетная проверка и сборка через временный каталог с простым путём.
- `Unity/Verification/` — фактические отчёты Editor/Player и четыре изображения из Player: [общий вид](../Unity/Verification/runtime.png), [река](../Unity/Verification/runtime-river.png), [вечер](../Unity/Verification/runtime-evening.png), [прогулка](../Unity/Verification/runtime-walk.png). Изображения получены прямым рендером камеры в RenderTexture; экранный интерфейс IMGUI в них не включён.

В экспорте Blender `(x, y, z)` преобразуется в Unity `(x, z, y)`, без изменения масштаба. Порядок индексов треугольников развёрнут из-за отражения базиса. Трансформации переводятся матрицей `S * M * S`, створки сохраняют точки вращения `x = ±30.5 м`, высоту `10 м`. Части разбиты по 60 000 вершин; загрузчик также поддерживает 32-битные индексы. Скачки транспортных порталов и переключение видимости не интерполируются сквозь город.

## Управление

`Play/Pause` воспроизводит или приостанавливает общий запечённый сценарий. `Open` проверяет отсутствие транспорта и посетителя на створках, затем продолжает согласованный цикл предупреждения, шлагбаумов, подъёма и прохода судна; останавливается перед опусканием. `Close` отклоняется при судне в канале и до окончания его прохода, затем продолжает опускание. Это управление безопасными фазами исходной постановки, а не независимая физическая симуляция свободного движения машин и судов. Автоматическое воспроизведение также проверяет занятую створку при каждом шаге движения и канал при опускании.

Ползунок `Daylight` меняет направленный и окружающий свет. `Overview` и `River` задают ракурсы, правая кнопка мыши вращает камеру, колесо меняет расстояние. `Walk`: WASD и мышь, Esc возвращает указатель и выходит из прогулки. Начальная точка находится на тротуаре подхода. CharacterController сталкивается с геометрией суши и створок; материалы воды, пены и следа не получают опорных коллайдеров. Проверка опоры запрещает шаг с края в реку. Ограничения по габаритам транспорта блокируют движение посетителя в автомобиль; общий сценарий приостанавливается, если автомобиль приблизится к посетителю.

## Проверка и воспроизведение

Из корня репозитория, в PowerShell:

```powershell
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' -b Tower_Bridge/Tower_Bridge.blend -P tools/export_unity.py
python -m unittest tests.test_unity_export -v
python Unity/compile_sources.py
```

На машине с активной лицензией Unity:

```powershell
./Unity/build_windows.ps1
# Другой установленный редактор можно указать параметром:
./Unity/build_windows.ps1 -UnityEditor 'C:/Program Files/Unity/Hub/Editor/6000.6.0f1/Editor/Unity.exe'
```

Скрипт копирует только `Assets`, `Packages`, `ProjectSettings` во временный ASCII-каталог, сохраняя редактируемый проект. Это обходит фактически выявленную ошибку Unity Linker с запятыми в пути данного репозитория. Временный каталог сохраняется для диагностики, отчёт копируется в `Unity/editor-build.log`, приложение — в `Unity/Build`. Метод `BridgeBuild.VerifyAndBuild` создаёт сцену, загружает настоящий экспорт и проверяет масштаб, две оси створок, машины, запреты открытия/закрытия, блокировку движения створок посетителем, коллайдер тротуара, отсутствие опоры в реке, приближение машин к посетителю и полный согласованный цикл. При успехе сохраняет `verification.json`. Проверки выбрасывают исключение при ошибке; это обычный пакетный EditMode harness без зависимости от скачиваемого Test Framework. В редакторе метод также доступен через меню `Tower Bridge → Verify export and build Windows`.

Для повторения программной проверки запустите приложение с `-force-d3d11 -force-driver-type-warp -verifyRuntime -logFile runtime.log` без `-batchmode`: последний не возобновляет `WaitForEndOfFrame`. Runtime harness повторяет проверки уже в Player, реально перемещает CharacterController к настилу и перилам, проверяет ракурсы, высоту глаз и дневной свет, сохраняет четыре PNG и `runtime-verification.json`, возвращает ненулевой код при ошибке. Изображения дополнительно проверяются на пустой чёрный кадр и розовый цвет отсутствующего шейдера. Обычный запуск `TowerBridge.exe` открывает интерактивную версию с управлением; флаг `-verifyRuntime` предназначен для автоматической проверки и завершает приложение. После успешного запуска выполните `python Unity/record_verification.py`: он сверит SHA исходного `.blend`, экспорт проекта, экспорт внутри сборки, отчёты, размеры PNG и обновит сводку с копиями доказательств.

## Фактическая проверка и ограничения

Семь Python-тестов прошли: оси, SHA исходника, диапазоны бинарных частей, конечные координаты, материалы, раздельные створки, количество кадров, точки вращения и изменение анимации. Исходники runtime и editor успешно скомпилированы установленным Roslyn против Unity `6000.6.0f1`, без предупреждений. Фактические Editor и Player проверки прошли, сборка Windows x64 создана; высота геометрии `67.45 м`, две створки, 14 машин. Сводка фиксирует SHA и перечень выполненных проверок. Первоначальная ошибка просроченного автономного права использования устранена обновлением лицензии в Unity Hub; обход лицензии не применялся. Официальный способ обновления Personal — [Unity Hub](https://docs.unity.com/en-us/hub/manage-license).

Процедурные узлы Blender заменены базовыми цветами Standard; отражения, цветовые вариации узлов, вечерние эмиссии и вода визуально не эквивалентны Cycles. Геометрия evaluated на первом кадре: деформации сеток, анимированные шейдеры, пена/след и мелкие колебания без выделенного actor-root не воспроизводятся покадрово. Трансформации отмеченных actor-root, включая колёса и двери, запечены на каждом кадре. Эти ограничения нужно оценить на настоящем runtime-изображении после активации, а не считать отсутствующими дефектами.

Не распространяйте каталоги `Library`, `Temp`, `Logs`, `UserSettings` и промежуточные DLL. Windows-приложение распространяется отдельным архивом вместе с `TowerBridge_Data`, `UnityPlayer.dll`, экспортом в StreamingAssets и результатами runtime-проверки. Исходный Unity-проект передаётся отдельно от этих временных каталогов.
